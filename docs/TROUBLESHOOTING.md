# 背景、通知與區網排查

## iPhone 仍中斷

先確認 App 內 C4 有有效車況、屏幕已連線、自動車況開啟，再開始背景連動。優先使用行車 GPS 模式並允許使用期間定位；看到動態島不代表 App 持續收到資料。不要用假車況／假心跳掩蓋失聯。

完全沒有可接受橋接回覆五分鐘會結束 iPhone 背景會話。車況顯示失效門檻仍為約 0.9 秒，不會放寬成五分鐘。系統暫停 App 時，連清屏都可能無法送出。回 App 記錄連線狀態與中斷時間；原有背景錯誤尚不能憑編譯通過宣稱已在實機解決。

## Android 沒通知

先按「3 秒後測試通知」，切到導航等待。這個測試不需要 C4 或 LED。

- 連通知列都沒有：檢查 App 通知權限、全域通知開關，以及「背景車況變更」頻道。
- 通知列有、沒有浮動橫幅：檢查頻道的重要性、車機浮動通知／勿擾／通知冷卻設定。車機可自行限制橫幅。
- 測試有、車況沒有：先確認 App 已在背景、自動車況開啟、新鮮有效車況確實改變，而且不是手動預覽。同事件不連續重複通知，快速變化最多每三秒取最新一筆。
- 常駐通知與事件通知是不同頻道。屏幕未連線不會單獨阻止有效車況通知。

複製診斷不包含連線金鑰；請另記車機型號、Android 版本、前景／背景狀態與發生時間。

## 和 CP 搭子寬螢幕版一起用時斷線

目前不能僅由現象認定是 C4 或 CP 搭子干擾。LED 使用 TCP 18765 的只讀橋接，導航 UDP 1999 是不同通道；不同埠不代表 Wi-Fi、路由、CPU 或車機省電不會互相影響。

Android LED 以每個 HTTP 請求選擇能到 C4 子網的網路，沒有全程序綁定網路，也不變更全域 Wi-Fi。依下列順序在相同位置／Wi-Fi 做對照：只開 LED、只開 CP 搭子、兩者同開。比較 HTTP 失敗數、延遲、有效車況數及 C4 CPU 負載。

C4 已有本專案檔案時，在其 Python 環境執行：

```sh
python3 diagnose_link.py --help
python3 diagnose_link.py --host 127.0.0.1 --seconds 30
```

預設讀 `/data/iphone-led/token`，輸出摘要不列金鑰或車況。若 C4 本機正常、Android 遠端失敗，優先查熱點／路由／車機限制；若 C4 本機也慢或 `valid:false`，查橋接與 carState 來源。避免同埠重複啟動橋接。
